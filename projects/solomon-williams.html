01 — Solomon Williams

System type: Serialized / Collectible Visual System

Project intro

A serialized jersey system presented as a family of front/back outputs with individualized identifiers and visual provenance markers.

The system

Rules

  • Deterministic identifier applied to each unit.
  • Front/back registration rules to ensure consistent alignment across outputs.

Inputs

  • Player name and jersey number (variable data).
  • Color palette determined by origin/state.
  • Base artwork assets for front and back layouts.

Variable elements

  • Player name
  • Jersey number
  • State color

Fixed elements

  • Layout grid
  • Type scale and lockups

How the system scales

The same rule set can generate one-off units or large serialized editions by swapping variable fields while retaining fixed layout and provenance marks.

Outputs

Front and back artwork, print-ready proofs, and web presentation tiles. The project supports proof sheets for registration checks and multiple export sizes for print and screen.

What changes from unit to unit

Visible differences are driven by variable fields (name, number, color). Provenance cues and deterministic marks remain consistent so units read as part of the same edition while preserving individual identity.

Production architecture

  • Tools: raster assets and print proofing workflows.
  • Automation/code: templating logic to place variable fields into locked layouts.
  • Print constraints: front/back registration and color management considered during export.

What the system makes possible

A repeatable production method that preserves individual identifiers while presenting a coherent, collectible family of objects suitable for print and digital presentation.
