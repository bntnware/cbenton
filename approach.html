Design the rule set. Then let the project expand.

1. Define the visual problem

Clarify what the project needs to communicate, how official or collectible it should feel, and where the work will appear.

2. Build the system

Create the visual grammar: layout rules, typography, colors, identifiers, data fields, edition logic, print constraints, and variation rules.

3. Generate the family

Apply the system across the required outputs while keeping each object coherent with the whole.

4. Proof the real production context

Test size, printing, sequencing, front/back registration, readability, and output behavior — not just a screen mockup.

5. Extend or hand off

Where appropriate, adapt the system into a reusable workflow, campaign framework, or integration for teams and collaborators.
